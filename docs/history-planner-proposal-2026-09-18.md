# PaperNexus：领域通用历史检索规划器方案

日期：2026-09-18。状态：设计提案，尚未实施或通过验证。本文修正上一份审计中的过强结论。

## 1. 决策与能力边界

建议采用：**短查询召回 + 有预算的迭代引文检索 + 证据约束路线提取**。

“领域通用”指各领域使用相同流程、预算与评分规则，检索词从实际文献提取；不指任意 1 篇论文都能唯一确定整个学科的完整历史。种子往往只定义一个局部研究问题。默认先输出与种子有关的历史和后续发展，更远的分支通过探索逐步发现。

独立判断：部分同意此前的过拟合担忧。证据支持当前结果跨领域不稳定，但不足以证明“问题主要在人工查询词”或“排序器已验证可泛化”。身份数据、评估口径、预算、召回、裁剪、排序和路线提取均存在混杂。

## 2. 之前测试中必须修正的地方

### 实测结果的正确解释

- Metalens 100%、Transformer 约 40%、AlphaFold 历史层 93.8% 均是特定基准与候选配置的测量，不能作为一般领域的准确率。
- `run_hybrid_ablation.py` 在读取路线结果后，再调用基准中的人工 queries 加入候选。93.8% 不是纯自动 pipeline 的召回率。
- AlphaFold 旧结果的 `max_nodes=25, neighbors_per_seed=8`；历史层结果为 `100, 25`。提升与预算扩大混杂，不能归因于历史回溯。
- 混合消融评估的是候选排序；实际路线仍调用 `routing.py` 中另一套分数与最短路径。候选 Recall@80 不能代表路线质量或阅读清单质量。
- 已经多次用 Transformer/AlphaFold 的结果选择方案，它们现在应作为开发回归集，不再称为未见过的测试集。

### 基准身份错误（本次通过 Crossref 核验）

| DOI | 当前基准描述 | 实际记录 |
|---|---|---|
| 10.1002/prot.25834 | trRosetta / interresidue orientations | Protein structure prediction using multiple deep neural networks in the 13th CASP，即 AlphaFold CASP13 工作 |
| 10.1126/science.add2187 | ESMFold 类结构预测 | Robust deep learning–based protein sequence design using ProteinMPNN |
| 10.1371/journal.pone.0028766 | Progress and Challenges… | Protein 3D Structure Computed from Evolutionary Sequence Variation |
| 10.1002/prot.340230303 | 1997 年 CASP 条目 | A large-scale experiment to assess protein structure prediction methods，1995 |

不要静默替换 v1 基准后继续引用旧指标。保留 v1，创建 v2，记录纠错与范围变更；错误 DOI 的命中不等于预期里程碑命中。难以匹配的重要论文在总体覆盖率分母中保留为未解决项，同时另报可解析子集召回。

### 可确认的工程问题

- OpenAlex 文档明确：未写布尔操作符的多个词默认按 AND 处理。拼接多个 Topics 和 review 会产生过强条件；不能据此得出“文本检索无效”。
- `_select_node_budget` 在检索/排序结束前裁掉论文，可能丢失路径中的连接节点；历史配额的剩余容量没有回填，所以节点上限 100 时可以只留下 77/82 个节点。
- `shared_seed_count` 被暂时用作综述参考频次，随后又被 `score_candidates` 覆写，语义不一致。
- 搜到较早的论文并不证明它是奠基工作；图中有入边和出边也不足以证明它是关键转折。
- 自动分支前缀曾选择 learning；分支词过滤仍含 Metalens 特例。应使用基于当前语料的词频与短语选择，逐步移除领域特例。

## 3. 可借鉴的成熟方法

| 方法/产品 | 借鉴内容 | 适用边界 |
|---|---|---|
| TARCiS，BMJ 2024 [1] | 前向、后向、共被引、共同参考文献检索的区分；迭代、去重与完整过程记录 | 引文检索不能单独保证完整召回；本项目是借鉴检索方法，不声称完成系统综述 |
| Wohlin 2014 snowballing 指南 [2] | 从相关种子出发，筛选新文献，再迭代追踪引文 | 扩展全部引用会爆炸，需要相关性筛选和预算 |
| Citationchaser [3] | 现成的前后向追踪工作流、可重复导出；论文解释其能补回术语不一致的相关研究 | 可参考流程；不将其依赖的远程数据服务视为免费稳定保证 |
| Local Citation Network [4] | 最接近可复用原型的开源参照：OpenAlex 等数据源、参考文献、引用者、间接引文网络、排序与 JSON 导出 | 提供局部网络和检索，不等于自动识别思想史；采用代码前单独审查许可证 |
| Litmaps 官方算法说明 [5] | 引文关联与 Similar Text 是互补的召回通道；低引论文可走语义通道 | 官方页面说明产品行为，不公开足以完整复刻的权重和质量评测 |
| MMR 多样性重排 [6] | 选少量互不重复的综述/锚点，避免都是同一小分支 | 只能减少冗余，不能证明历史重要性 |
| 引文主路径分析相关研究 [7] | 在已取得的引文图中提取知识发展的主干 | 缺失图上会放大偏差；首版不把“主路径”当真实因果链 |
| SPECTER，ACL 2020 [8] | 用引文信号训练论文表示，可作为 BGE 的后续对照 | 论文表征的提升不能解决未召回节点；现阶段不急于换模型 |

商业定位修正：Litmaps、ResearchRabbit 已有从种子逐步探索与持续组织文献的体验。持久地图是必要体验，但不是独占优势。我们的待验证优势是：历史路线更易核查、跨分支连接更清晰、缺口更透明、已探索部分可复用。

## 4. 架构：规划检索动作，而非只生成关键词

```text
1–3 篇种子
  -> 身份解析与默认范围
  -> 直接引文候选 + 短文本查询 + 综述候选
  -> 选择相关且多样的锚点
  -> 两轮有预算的后向追踪 / 共被引补充
  -> 去重后的完整候选池与证据
  -> 局部历史图与后续分支
  -> 3–8 篇路线、关键节点候选、优先阅读清单
  -> 增量并入已有 Atlas
```

### A. 身份与范围

采用内部稳定 paper_id，单独保存 DOI/OpenAlex/arXiv 别名及原始记录。预印本和正式版关联，保留各自年份与引文来源；不能修改标题/年份却沿用另一篇论文的引文图。发现冲突时仅对这些记录使用 Crossref/arXiv/出版方元数据补查；这些服务验证身份，不自动提供缺失引文。

默认以“种子论文解决的问题/采用的方法”为范围。多种子按各自分支建立子范围，再合并并显示真实桥接关系；无法连接时允许两条路线并存。可选的主题说明能改善结果，但不是强制输入。

### B. 短查询及召回通道

1. **直接引用通道**：读取种子参考文献，按每个种子保留机会；取得一定数量的引用者，区分早期后续与较新后续，避免仅取总引用最高的结果。
2. **文本通道**：从标题、摘要和可信邻居提取 2–4 个短语组。TF-IDF/n-gram 提取后用已缓存 BGE 做相关性排序和 MMR 去冗余；每个短查询只表达 1–2 个概念。同义词 OR，不同约束 AND，不拼接全部 Topics。
3. **综述锚点通道**：一部分查询查核心概念本身，一部分查核心概念 AND (review OR survey OR overview)。再依据标题/摘要和文献类型筛选 2–4 个主题相关、年代和覆盖面不同的综述/综合论文。搜索结果含 review 一词不等于它就是综述。
4. **语义召回备选**：OpenAlex 当前文档提供 search.semantic，可把种子摘要作为输入进行后续对照 [10]。它是外部召回；本地 ONNX 只能重排已经取得的论文。上线前测覆盖、费用、稳定性，不默认依赖。

关键设计：现代术语用于找到入口，不要求所有祖先论文也包含现代术语。对 BERT，较早的词向量、序列建模、attention 工作应主要经已检索论文的真实参考文献进入，不能硬编码这些历史论文清单。

### C. 有预算的回溯

维护动作队列，每个动作包含 kind、anchor_id/query、direction、depth、time_window、预计请求数和执行来源。动作包括 references、citers、short_search、survey_search、identity_lookup。

首版固定执行顺序：身份检查 -> 每种子直接邻域 -> 短查询/综述 -> 每个分支选少量锚点 -> 最多两轮后向追踪。每轮按“新增且去重的相关节点/实际请求数”记录收益；后续才考虑自适应调度或 bandit，不在首版训练调度模型。

历史锚点优先级结合：被多个相关锚点独立引用、与局部问题相关、连接种子路径、补充此前未覆盖的年代/分支。先确认相关，再考虑年代。论文很早或总引用很高都不能单独入选。

共同参考支持按引用论文去重，避免同一论文被多个查询找到而重复投票；预印本/正式版不重复投票；对长参考文献表采用归一化，避免一篇长综述支配结果。

可观察停止规则：两轮结束、预算耗尽、或连续两批边际新增很少。饱和仅说明当前检索策略收益下降，不能宣称找到了学科起源。输出明确停止原因与未解析记录。

### D. 候选池与证据图分离

保留完整候选元数据和发现日志，再选择显示节点；不要为了 UI 的 80 个节点提前删掉知识池。连接路线所需的中间节点在图提取时保留。

- 真实引用边：文献元数据支持，有方向，可构成 citation_path。
- 语义/共被引/共同参考边：支持主题关联，显示在探索视图，不冒充历史继承。
- 方法继承/解决局限/关键转折：需要正文引用上下文支持。未取正文时只输出候选，不下确定结论。

首版路线采用带长度上限、相关性和去冗余约束的种子路径搜索，优先保留有证据的中间步骤；不只选择最短路径。最多 2–3 条短路线，断点如实显示，不靠年代或语义强行补边。低引桥接论文用局部连通作用提示，而不是按总引用数隐藏。

### E. Atlas 的增量生长

SQLite 保存论文、来源记录、关系、检索动作、查询指纹、embedding 版本、已探索前沿和运行配置。统一候选与图接口，使 CLI 和未来 FastAPI 调用同一服务。

缩放、拖动、展开已缓存内容不调用远程 API。只有“继续回溯/探索此分支/刷新”执行新动作；同一分支同一输入和版本命中缓存，不重复编码。不同种子产生的图按稳定身份合并，新增证据可加强已有关系，不能凭合并自动创造引文。

## 5. 技术、预算与替代方案

沿用 Python、requests、NetworkX、SQLite、FastEmbed/ONNX、BGE-small。候选池约几百篇不需要 Neo4j 或独立向量数据库；不需要本地大语言模型，也不需要付费 LLM key。

初始预算是待验证配置，不是实测承诺：

- 每任务最多 6 次文本搜索，其他调用用于身份解析、引文批量获取和后向扩展。
- 总 HTTP 尝试数上限建议 30，失败重试也计入；另外记录请求费用/额度和总截止时间，具体随 OpenAlex 配额调整。
- 完整候选池上限先设 500；批量编码标题/主题，摘要精排最多 150 篇；前台显示 40–80 个节点、阅读清单约 10 篇。
- 外部重试必须受任务总时间限制；到 8 分钟开始整理已有结果，预留时间在 10 分钟内返回部分或完整结果。
- 只对未缓存文本编码。历史本机实测 250 篇全文本编码约 23.3 秒、缓存约 0.084 秒；500 篇的阶段化方案耗时尚未实测，不能线性外推作产品 SLA。

OpenAlex 文档当前区分 search 与 filter 的费用 [9]，因此动作预算不能只数“查询条数”。共享服务器上的 key 由后端持有，网页访客无需填写；后续上线设置任务额度和全局额度。

路线比较：

| 方案 | 优点 | 问题 | 决策 |
|---|---|---|---|
| 只改搜索词 / 让 LLM 自由搜 | 开发快，能提出术语 | 易漂移，历史边不可核查，成本不稳定 | 可选一次术语建议，非首版核心 |
| 无限制引文滚雪球 | 不依赖领域字典 | 高度数节点导致爆炸，数据缺口仍存在 | 不采用无界扩展 |
| 短查询 + 限深引用追踪 | 可控、可解释、复用现有代码 | 仍需范围判断、身份清洗与评估 | 推荐首版 |
| 更换 SPECTER / 建全库向量索引 | 可改善相似性表示或召回 | 不能先解决基准和身份错误，部署成本增加 | 候选覆盖问题解决后再对照 |

## 6. 验证设计与开发顺序

目标对象：在不完整文献图中，从种子得到相关子图及有证据路径。仅引文和摘要无法唯一识别思想继承，故首版可验证承诺是“可核查引用路线 + 历史候选”，不是完整因果历史。

误差链：身份错配 -> 图错配 -> 候选错误 -> 路线错误。上游错误不能靠下游排序补救。完整元数据的理想情形可计算路径，但缺失边仍需外部补证，不能由相似度制造。

**第一步：修测量。** 新建基准 v2；逐条核对 DOI/标题/年份/领域角色及外部选择依据。区分祖先、后续发展、旁支。BERT 的历史测试不应因未找到 FlashAttention 而扣历史分，应在后续发展覆盖中单独计算。保留所有身份失败作错误类别。

**第二步：公平 A/B。** 固定同一数据快照、同一实际请求预算、相同候选/显示容量，比较 A=直接邻域，B=邻域+短查询，C=B+两轮引文回溯。保持下游排序不变。记录 raw_retrieved、resolved、deduplicated、candidate_selected、route_selected 各阶段损失，定位是否真的缺召回。

**第三步：端到端与未见领域。** 开发集采用 Metalens/Transformer/AlphaFold；由至少两份独立综述/权威回顾建立第四领域基准，冻结后才第一次运行，禁止将答案 DOI/标题注入查询规划器。没有独立专家时，清楚标注这是弱参考标准。后续在该领域调参后再找新留出集。

同时测：非种子历史里程碑召回、后续分支覆盖、Top10/20 相关性、路线有证据边比例、元数据冲突、每种子覆盖、去重质量、请求/耗时/缓存增益。所有指标报告分子分母与每个领域结果，不能只报宏平均。

此前提出的 80%/75% 是项目内部目标，不是学界公认门槛；重新登记后仅作为开发诊断。最短路径真实存在也不等于“演进准确率”。审查 Top20 与关键边时保留来源，不让同一 LLM 同时生成答案再独自证明答案。

## 7. 与 Web 原型的关系

不建议继续无限期用召回率阻止原型。先完成基准纠错与一轮公平回溯实验，然后开发可部署的本地 Web Alpha，将算法作为可替换服务。

本地 Alpha 应能：输入种子、查看解析结果、等待任务、浏览有证据路线/探索图/清单、继续扩展并保存地图。跨领域弱项明确标为实验性，不宣称穷尽历史。

你自用之后，再部署网页邀请他人反馈“路线和阅读清单是否有用”。网上多人使用还需服务器保存地图、任务队列、请求预算和用户数据隔离；只发布静态页面不足以承载当前检索服务。商业发布的范围承诺和实际验证保持一致。
