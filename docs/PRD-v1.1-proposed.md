# ScholarTree / PaperNexus PRD v1.1 建议稿

状态：验证版，不作为直接承诺上线的范围。  
首发形态：Web。  
首要用户：已有 1–3 篇种子论文、正进入陌生细分方向的硕博研究生。

## 1. 产品目标

用户输入 1–3 篇种子论文后，在 10 分钟内获得：

1. 一条可核查的研究演进路线。
2. 关键前驱、转折论文和近期分支。
3. 按优先级排列的阅读清单及“为什么应读”。
4. 可保存、编辑、导出和分享的研究项目。

所有引用事实可回到论文节点；所有 AI 判断明确标注来源和置信状态。

### 非目标

- 不承诺还原完整学术史。
- 不把引用等同于因果、认同或启发。
- 不自动生成可直接提交的系统综述。
- 首版不做 Windows 客户端、实时多人协作、全量全文托管和自动视口 LLM。

## 2. 核心价值与成功指标

核心任务：帮助用户决定“先读什么、为什么读、这条路线如何发展”。

北极星指标：每周完成的**有效研究路线**数量。有效路线要求用户至少保存、导出或加入待读 3 篇论文。

Alpha 门槛：

- 种子识别成功率 ≥95%。
- 首个可操作骨干图 P95 <30 秒。
- Top 20 用户相关率 ≥60%。
- 关键路径专家覆盖率 ≥70%。
- AI 事实无支持率 <5%。
- 首次会话有效发现率 ≥40%。
- 两周主题复用率 ≥30%；四周留存 ≥15%。
- 数据和模型可变成本 <付费收入 15%。

## 3. 信息模型

### 3.1 论文节点

必需字段：

```text
id, canonical_ids, title, authors, publication_date,
work_type, venue, abstract, abstract_source,
cited_by_count, fwci, citation_percentile,
counts_by_year, topics, is_retracted,
best_oa_location, data_sources, updated_at
```

### 3.2 边

原始边与派生边必须分离：

```text
edge_type: citation | co_citation | bibliographic_coupling |
           semantic_similarity | inferred_relation
raw_direction: citing -> cited
display_direction: earlier -> later  # 仅 influence-flow 视图
evidence: source IDs / citation context / abstract sentence
relation_label: uses | extends | compares | supports | disputes | unknown
confidence: high | medium | low | unavailable
```

没有引用上下文时，`relation_label` 默认为 `unknown`。

### 3.3 图版本

每次扩展生成新版本，保存种子、时间窗、节点预算、候选来源、剪枝参数、数据源时间、算法版本和父版本，以支持撤销与复现。

## 4. P0 用户流程

1. 创建项目并输入 1–3 篇种子，或导入 BibTeX/RIS。
2. 选择候选论文，处理同名与版本合并。
3. 先展示 10–20 个骨干节点和任务进度。
4. 后台补齐 50–100 个探索节点。
5. 用户切换“影响力 / 桥接 / 近期进展 / 与种子相关”视图。
6. 点击节点查看证据，标记待读、已读、收藏、排除或备注。
7. 用户主动点击“解释当前路线”，获得带论文编号的叙事。
8. 导出阅读清单、BibTeX/RIS/CSV、图片或分享链接。

## 5. 功能需求

### F-101 多标识符种子解析（P0）

支持 DOI、arXiv ID/URL、PMID、OpenAlex ID、标题和通用论文 URL。候选列表显示匹配置信度。使用 DOI、标题、作者、年份和来源进行多字段交叉校验。arXiv 先解析其规范元数据和 DOI，再映射到 OpenAlex；无 DOI 时使用多字段匹配并要求用户确认。

验收：100 个跨学科标注种子中，正确候选 Top 1 ≥95%；错误版本合并 <1%。

### F-102 多种子与文献库导入（P0）

支持 1–3 个种子、BibTeX 和 RIS。Zotero 连接列为 P1。

### F-103 候选生成与渐进构图（P0）

候选来源包括直接参考文献、后续引用、共被引、文献耦合和语义相似。节点预算默认 80，可在 30–150 间调整；稀疏主题允许少于 30。先返回骨干图，再渐进补齐。

每个节点必须提供 `selection_reason`。

### F-201 多维排序（P0）

- 影响力：年份/领域归一化指标。
- 桥接：当前采样图中的介数和跨社团连接。
- 相关性：与种子语义、引用距离和多种子覆盖。
- 新近性：最近两个完整自然年的平均引用量取 `log1p`，再按领域与论文年龄归一化；设置最低观察期和样本量。

不提供未经验证的固定综合权重。默认权重通过离线标注集确定，并允许用户切换模式。

### F-202 时间演进布局（P0）

X 轴为发表时间，缺失月份时只定位到年份区间。Y 轴为 Leiden 聚类后的稳定泳道。默认只显示骨干引用边；其他关系通过图例筛选。

动态扩展保持已有节点坐标，新增节点局部布局。

### F-301 三层语义缩放（P1）

- 领域层：聚类、主题、时间跨度、代表论文和数量。
- 路线层：骨干论文、关键路径和主要引用边。
- 论文层：标签、边证据和元数据。

阈值按当前密度和标签碰撞动态决定。提供面包屑、迷你地图、返回上级、重置和减少动画。

### F-401 论文证据抽屉（P0）

显示元数据、摘要来源、入选原因、关系证据、数据更新时间、撤稿状态和 OA 来源。提供阅读状态、收藏、排除、备注、引用导出和打开原文。

### F-402 关键路线（P0）

从早期前驱到种子、再到近期后续提取 1–3 条路线，每条 5–10 篇。路线以相关性、时间一致性、多种子覆盖和边证据排序。用户可锁定或替换节点。

### F-403 可撤销扩展（P1）

系统先从种子标题检索、引用邻居和 `related_works` 构建不进入主图的候选光环，结合语义近邻与引用边生成 5–12 个“探索前沿”提案。每个提案显示主题词、代表论文、时间跨度、预计新增节点和检索依据。

用户选择向前追溯、向后追踪或展开某个相邻分支后，系统才执行该分支的二次检索。每个分支默认最多使用 2 个短查询并受项目请求预算约束；结果在分支内部排序，不参与单一全局榜单竞争。扩展后生成图版本，可撤销。

底层领域库保存项目发现过的全部论文和关系；主干路线、分支视图和阅读清单是同一领域库上的独立视图。候选光环、已确认地图和隐藏归档必须分层，避免自动扩展形成不可读的大图。

### F-501 按需可信叙事（P0）

用户主动触发。输出“背景、突破、承上启下、争议/证据不足”，每句话包含节点编号。缺少摘要或上下文时不推断单篇贡献。

缓存键：排序后的节点与边 + 图版本 + 数据版本 + 模型 + Prompt 版本 + 语言 + 输出模式。

### F-601 研究工作流（P0）

项目保存、阅读状态、备注、导出和分享。公开分享默认关闭；用户可随时删除项目和账户数据。

### F-701 产品分析与反馈（P0）

记录构图成功率、首图时间、保存/导出、相关性反馈、重复主题、LLM 成本和失败原因。不记录未发表研究内容本身作为分析事件。

## 6. 异常与降级

- 新论文无后续引用：展示已知前驱，明确数据截止时间。
- 摘要缺失：不生成论文贡献判断。
- 标识符冲突：要求用户确认，不自动选第一项。
- 429：读取 `Retry-After` 和额度信息；日预算耗尽时停止重试并说明恢复时间。
- 上游失败：返回已完成阶段和部分图；已缓存项目进入只读模式。
- 图不连通：分支显示为独立路线，不制造虚假连接。
- 节点超预算：让用户替换、收起或创建新分支。
- 撤稿：显著标记，并默认从推荐优先级中降权。

## 7. 建议架构

```text
React + TypeScript + Sigma.js
        |
        | REST + SSE/fetch stream
        v
FastAPI API
        |
        +-- async worker: ingestion / graph / narrative
        +-- PostgreSQL: user/project/version/feedback
        +-- object/cache store: graph snapshots
        +-- OpenAlex primary metadata
        +-- Crossref / Semantic Scholar optional verification
        +-- LLM provider abstraction
```

Alpha 可用 SQLite 和单 worker 降低成本，但接口仍按异步 job 设计。浏览器中的 IndexedDB 只缓存最近项目，不作为唯一事实源。Tauri 在产品市场匹配后再评估。

## 8. API 草案

```text
POST   /api/v1/seeds/resolve
POST   /api/v1/graphs
GET    /api/v1/jobs/{job_id}
POST   /api/v1/jobs/{job_id}/cancel
GET    /api/v1/graphs/{graph_id}?version={n}
POST   /api/v1/graphs/{graph_id}/expansions
POST   /api/v1/graphs/{graph_id}/undo
POST   /api/v1/narratives
GET    /api/v1/narratives/{id}/stream
PATCH  /api/v1/projects/{id}/papers/{paper_id}
POST   /api/v1/projects/{id}/exports
```

所有变更请求支持幂等键。所有图和叙事响应包含 provenance、算法版本、构建时间和数据截止时间。

## 9. 开发与验证顺序

### Gate 0：无访谈异步验证（2 周）

建立种子提交页，在后台使用现有工具和半人工流程完成 15 份可核查路线，通过只读链接交付。记录用户是否打开至少 3 篇论文、加入待读、导出、标错和在 14 天内提交第二个主题，不要求同步访谈。

至少获得 30 次有效提交；≥40% 的结果触发加入待读或导出，≥20% 在 14 天内复用，并获得至少 5 次真实付费或可退订金后进入完整 Web Alpha。详细流程见 `docs/no-interview-validation-and-mvp-plan.md`。

### Gate 1：数据原型（可与 Gate 0 并行，2 周）

构建跨三个学科的 20 主题标注集。达到种子识别、相关率、关键路径和事实支持率门槛。

### Gate 2：Web Alpha（4 周）

完成 P0 的种子解析、渐进骨干图、证据抽屉、阅读状态、导出、项目保存和埋点。

### Gate 3：可信叙事与付费（4 周）

加入按需叙事、引用编号、错误反馈、成本计量和真实价格实验。

连续两轮未达到留存或付费门槛时，收缩为一次性“研究路线报告生成器”，停止复杂 LOD 与桌面端开发。

## 10. 商业假设

- 免费：每月 3 个项目、每图 100 篇、有限解释次数。
- 学生 Pro：29–49 元/月；国际 6–10 美元/月。
- BYOK：允许高级用户自带 LLM key，数据源成本仍受产品配额控制。
- 实验室版：只在共享、权限和复用需求出现后测试。

付费点是可验证路线、可复用项目、导出和持续监控，而不是单纯更多节点。

## 11. 发布前必备

- 隐私政策、服务条款、数据删除和模型供应商披露。
- PDF 与摘要的许可证处理；默认链接来源，不缓存无权再分发的全文。
- 建立“来源 × 字段 × 展示/缓存/LLM 用途 × 许可 × 保留期”矩阵，尤其覆盖 OpenAlex 摘要、Semantic Scholar 数据和第三方 PDF。
- API key 只存服务端，用户 BYOK 使用加密存储或仅会话使用。
- 速率限制、滥用控制、成本告警、日志脱敏和备份恢复。
- 对 `ScholarTree` 与 `PaperNexus` 做正式商标和域名检索。
