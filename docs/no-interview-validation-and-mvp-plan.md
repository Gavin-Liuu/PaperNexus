# PaperNexus 无访谈验证与核心 MVP 方案

日期：2026-09-17

## 1. 已确认的核心承诺

> 输入 1–3 篇种子论文，在 10 分钟内得到一条可核查的研究演进路线、关键转折论文和优先阅读清单。

“10 分钟”指产品自动化后的用户等待时间。验证阶段可以由人工和现有工具在后台完成，但交付物必须与未来产品一致。

## 2. 什么是人工研究路线交付

它是一种 Concierge / Wizard-of-Oz MVP：先不开发完整算法和交互，由你用现有工具半人工完成结果，让用户只看到最终价值。目的不是提供长期人工服务，而是确认用户究竟会使用哪些结果。

### 输入

- 1–3 篇 DOI、arXiv、URL 或标题。
- 可选研究目的：入门、写 related work、找技术前驱、找近期进展。
- 可选范围：只追溯、只看后续、双向；语言；时间范围。

### 半人工流程

1. 用 OpenAlex / Local Citation Network 获得前后向引用候选。
2. 用 Connected Papers 或同类方法补充文献耦合、共被引和相似论文。
3. 合并版本、去重、排除明显不相关和撤稿记录。
4. 从候选中选择 12–20 篇，组成 1–3 条连续路线。
5. 检查每条路线中的直接引用边；没有证据时标成“相似”或“推断”，不画成引用。
6. 用摘要、引用上下文或原文支持“解决了什么、承接了什么”的说明。
7. 按“必读、背景、前沿、可选分支”排列阅读顺序。

### 每份交付物

1. **演进路线图**：6–12 个骨干节点，其他论文作为可展开分支。
2. **转折论文卡片**：论文、角色、被选原因、证据、置信状态。
3. **优先阅读清单**：8–12 篇，包含阅读顺序和“为什么读”。
4. **证据表**：每条边的类型、方向、来源和数据时间。
5. **脉络说明**：背景、转折、分化、当前前沿；每句话带论文编号。

验证阶段每份可以花 30–60 分钟制作。若这个结果没人保存、打开论文或再次使用，把流程自动化到 10 分钟也没有商业价值。

## 3. 无法访谈时如何验证

没有同步访谈仍可验证；完全没有真实用户则只能验证技术，不能验证需求与付费。

### 阶段 A：离线真值集

先选一个你能判断质量的细分领域，不要一开始跨所有学科。准备 20 个主题，每个主题 1–3 篇种子，并从综述、课程阅读单或专家公开书单建立参考路线。

比较以下基线：

- 仅按总引用量。
- Citation Gecko 风格的共同前驱 / 共同后继计数。
- Personalized PageRank。
- 当前的多维候选排序。

记录 `nDCG@10`、关键论文召回率、路线断边率、版本重复率和无证据陈述率。该阶段只证明算法是否比简单基线更好。

### 阶段 B：异步 Concierge

建立一个极简提交页或表单：用户提交种子和邮箱，你在 24 小时内返回只读结果链接。无需电话、会议或开放式访谈。

结果页只收集行为：

- 是否打开至少 3 篇论文。
- 是否把至少 3 篇加入待读。
- 是否导出 BibTeX / CSV / 图片。
- 是否标记错误关系。
- 14 天内是否提交第二个主题。

可以附两个单选题：“这份路线是否比你原来的检索更快？”和“最没用的是哪一部分？”。不要依赖长问卷。

### 阶段 C：自助 Alpha

只自动化种子解析、骨干路线、证据抽屉和阅读清单。通过 GitHub README、学校社群、研究工具社区或公开示例地图引流，使用埋点观察完整漏斗：

```text
到达 -> 成功解析种子 -> 生成路线 -> 打开论文
     -> 加入待读/导出 -> 第二次建图 -> 付费
```

### 阶段 D：真实价格实验

先测试一次性报告价格，再测试订阅。文献梳理可能是低频任务，直接假设月订阅风险较大。

- 免费：首次路线或公开示例。
- 单次深度路线：9.9 / 19.9 / 29.9 元三档实验。
- 当 14 天内重复建图比例足够高时，再测试 29–49 元/月。

付款、可退订金或真实结账页的行为证据强于“愿意付费”问卷。

### 无访谈继续门槛

首批至少获得 30 次有效提交，其中 15 份完成交付：

- ≥40% 的结果触发加入待读或导出。
- ≥30% 的用户打开至少 3 篇推荐论文。
- 错误关系主动标记率 <10%。
- ≥20% 在 14 天内创建第二个主题。
- 至少 5 次真实付费或可退订金。

若只能获得点赞和“看起来不错”，但没有打开、保存、导出、复用或付款，不应继续开发复杂缩放和桌面端。

## 4. 竞品与 GitHub 项目应带来的方案改进

| 来源 | 应吸收的机制 | 对 PaperNexus 的具体改进 | 不应直接照搬 |
|---|---|---|---|
| Connected Papers | 将相似图与引用树明确区分；从大候选池选少量相关论文 | 提供“演进路线”和“相似探索”两个视图，边类型永远不混用 | Force layout 不能表达可靠时间顺序 |
| Citation Gecko | 多种子、共同前驱/后继、发现后加入 seed、BibTeX/Zotero | 1–3 个 seed 是默认入口；共同前驱成为“基础候选”，共同后继成为“近期候选” | 技术栈陈旧；README 称 MIT，但根目录许可证文件需进一步确认 |
| Local Citation Network | 图+表双视图、Top Cited/Top Citing、数据时间、完整度、撤稿提示、CSV/RIS/JSON | 所有图都配可排序表；明确数据覆盖与撤稿；支持研究资料导出 | GPL-3 代码不适合直接并入计划闭源的商业产品 |
| Inciteful | Literature Connector、最短路径、引用网络分析 | 增加“这两篇论文如何连接？”并输出可核查路径 | 前端为 AGPL-3；直接修改并作为网络服务会带来源开放义务 |
| ResearchRabbit | 集合、继续探索、用户相关性反馈、Zotero | 把相关/不相关反馈用于候选重排；项目可持续生长 | 推荐、收藏本身已经商品化，不能作为主要卖点 |
| Litmaps | 时间过滤、监控、分享、工作区 | P1 加入新论文提醒和分享链接 | 首版不要复制完整监控与团队系统 |
| Semantic Scholar | influential citation、citation context / intent | 用户点边时按需补充“使用/比较/支持/反驳”等证据 | 不能把模型分类称为因果事实；商业许可先核对 |
| scite | 引用上下文与 supporting / contrasting / mentioning | 将边从“有/无”升级为“有何含义”，并显示原文上下文 | 不应伪造或仅凭摘要推断引用意图 |
| CiteSpace / VOSviewer | 时间 overlay、突现、中心性、聚类稳定性 | 作为算法基线与专家模式，不作为新手主界面 | 专业文献计量 UI 学习成本高，不适合作为主工作流 |

商业闭源时，优先使用 MIT/Apache 类基础库，如 Sigma.js、Graphology、React 和 NetworkX；对 GPL/AGPL 项目吸收公开方法和交互思想，自行实现，不复制代码。最终许可证决策仍应由正式法律审查确认。

## 5. 核心功能的产品结构

### 5.1 一个图承担两种任务会失败

分成两个相邻视图：

- **路线视图**：只显示有时间和证据支持的骨干演进路径。
- **探索视图**：显示相似论文、共被引、文献耦合和旁支。

默认进入路线视图。用户需要扩大检索时再进入探索视图，并可把论文固定进路线。

### 5.2 论文角色

- **基础论文**：被多个 seed 或骨干节点共同引用，且与主题相关。
- **转折候选**：连接前后阶段或多个主题簇，并有直接引用路径和内容证据。
- **桥接候选**：当前采样图中连接两个分支；必须显示“局部指标”。
- **前沿论文**：近期、与 seed 高相关且引用多个骨干节点。
- **分支论文**：相关但不属于主路线，默认收起。

“关键转折”不由单个介数分数决定。至少满足：结构信号、时间一致性、主题变化和文本证据中的两项，并将理由展示给用户。

### 5.3 自动构建流程

```text
解析 1–3 个 seed
  -> 版本合并与标识符校验
  -> 拉取直接前驱/后继
  -> 补充共被引、文献耦合、语义相似候选
  -> 全局预算下选择 50–100 篇
  -> 构建早期到晚期的引用 DAG
  -> 提取 1–3 条、每条 5–10 篇的骨干路线
  -> 为转折候选收集摘要/引用上下文证据
  -> 生成分层阅读清单和带编号叙事
```

单种子路线建议为 `2–3 篇基础 -> seed -> 2–3 篇后续/前沿`。多种子优先寻找共同基础、种子之间的连接论文和各自分化的后续分支。

### 5.4 优先阅读清单

| 层级 | 数量 | 目的 |
|---|---:|---|
| 先读 | 3–5 | seed、核心转折和理解全局所需论文 |
| 补背景 | 2–4 | 共同前驱、方法基础和术语来源 |
| 看前沿 | 2–4 | 近期后续与当前分支 |
| 可选分支 | 0–5 | 相关但不在主路线的方向 |

每篇显示 `入选原因`、`与哪篇相连`、`预计阅读价值`、`证据状态`，不显示一个无法解释的总分。

## 6. 最小可用界面

首版只需要四个主要状态：

1. **输入页**：1–3 个 seed、目的、方向和时间范围。
2. **构建进度**：解析、候选、路线、证据四个阶段；骨干先出现。
3. **工作台**：左侧路线/探索切换，中间时间图，右侧证据抽屉。
4. **阅读清单**：先读/背景/前沿/分支，可导出 BibTeX、CSV 和图片。

首版暂缓宏观气泡、连续 LOD、粒子动画、桌面端、团队协作和自动平移触发的 LLM。验证“路线、转折、清单”确实被使用后，再加入语义缩放。

## 7. 建议的四周实现范围

### 第 1 周：数据与路线基线

- DOI / OpenAlex / 标题解析；arXiv 规范化。
- 多种子前后向一跳候选。
- Citation Gecko 风格共同前驱/后继基线。
- 固定测试集和质量记录。

### 第 2 周：可核查路线

- 时间 DAG 和 1–3 条骨干路径。
- 论文角色与入选原因。
- 抽取式证据和“证据不足”状态。
- 优先阅读清单。

### 第 3 周：可用 Web 工作台

- 时间图、表格、证据抽屉。
- 相关/不相关、待读、排除。
- BibTeX / CSV / 图片导出。

### 第 4 周：异步验证

- 提交页、只读分享链接和匿名行为事件。
- 30 次提交的 Concierge / Alpha 混合交付。
- 一次性价格实验和每份结果成本记录。

四周目标是验证核心承诺，不是发布成熟商业软件。达到复用和付费门槛后，再进入账户、订阅、监控、Zotero 深度集成与语义缩放。

## 8. 当前决策

- 保留核心承诺。
- 首发聚焦一个细分领域和 Web。
- 将访谈门槛替换为异步行为门槛。
- 先验证单次交付价值，再验证订阅。
- 将“关键转折论文”做成有理由、有证据、有置信状态的候选，而非算法裁决。
- 把路线与相似探索分成两个视图。
